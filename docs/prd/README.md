# FBKR Learning Centre Portal PRD

이 디렉터리는 승인된 제품 요구사항을 개발 단계별로 분리해 관리한다. 개발 일정은 첨부 설계도의 일정을 사용하지 않으며, 각 단계는 앞 단계의 인수 기준을 통과한 뒤 진행한다.

| 단계 | PRD | 목적 | 상태 |
| --- | --- | --- | --- |
| Phase 1 | [기반·인증·사용자 관리](./phase-01-foundation-auth-users.md) | 포털 기반, 로그인, 권한, 계정 관리 | 진행 중 |
| Phase 2 | [교육과정·차수·신청 운영](./phase-02-course-session-enrollment.md) | 과정 개설부터 승인·배정·취소까지 | 대기 |
| Phase 3 | [출결·수료·수료증](./phase-03-attendance-completion-certificates.md) | 출결 확정, 수료 판정, 수료증 발급 | 대기 |
| Phase 4 | [알림·자료·이력·운영 자동화](./phase-04-notifications-history-operations.md) | 알림, 번역, 자료, 과거 이력, 감사·운영 자동화 | 대기 |

## 공통 제품 원칙

- 서비스명은 `FBKR Learning Centre Portal`이다.
- 사용자 화면, 데이터 모델, 문서에서는 `차수`라는 용어를 일관되게 사용한다.
- 교육담당자와 참가자 모두 PC 웹을 사용할 수 있고, 참가자 주요 흐름은 모바일에서도 쉽게 사용할 수 있어야 한다.
- 한국어와 영어를 지원하며, 회사 CI 기반 색상과 Arial 글꼴을 사용한다.
- GitHub 비공개 저장소, Supabase, Vercel을 기본 운영 환경으로 사용한다.
- 보안과 감사 기능은 MVP에서 구축하기 쉬우면서도 비밀키 노출과 권한 우회를 방지하는 형태를 우선한다.
- 모든 공개 스키마 테이블에는 RLS를 적용하고, 브라우저에 관리자용 비밀키를 노출하지 않는다.

## 상태 관리 규칙

- 각 PRD의 `개발 추적` 항목을 실제 구현·검증 결과에 맞춰 갱신한다.
- 범위가 변경되면 코드보다 먼저 해당 PRD의 요구사항과 인수 기준을 수정한다.
- 단계 완료는 코드 작성만으로 판단하지 않고 단위 테스트, 데이터베이스 테스트, 빌드, 핵심 사용자 흐름 검증을 모두 통과해야 한다.
