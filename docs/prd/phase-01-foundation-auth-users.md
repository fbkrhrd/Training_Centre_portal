# Phase 1 PRD — 기반·인증·사용자 관리

## 1. 목표

직원이 개인 사번과 비밀번호로 안전하게 로그인하고, 역할에 맞는 포털 화면을 사용하며, 시스템 관리자와 교육담당자가 개별 또는 Excel·CSV 방식으로 계정을 관리할 수 있는 제품 기반을 구축한다.

## 2. 사용자와 권한

| 역할 | 핵심 권한 |
| --- | --- |
| 시스템 관리자 | 전체 사용자 조회·생성·수정·비활성화, 전체 관리 메뉴 접근 |
| 교육담당자 | 사용자 조회·생성·수정·비활성화, 담당 교육 운영 메뉴 접근 |
| 참가자 | 본인 정보와 언어 설정, 비밀번호 변경, 참가자 메뉴 접근 |

역할은 사용자가 수정할 수 없는 Supabase Auth `app_metadata`에 저장한다. 재직 상태가 비활성이면 로그인 또는 포털 진입을 차단하되 기존 이력은 삭제하지 않는다.

## 3. 핵심 사용자 흐름

### 3.1 로그인과 비밀번호

1. 사용자는 개인 사번과 비밀번호를 입력한다.
2. 최초 비밀번호는 사번과 동일하게 설정한다.
3. 로그인 후 사용자는 원하는 시점에 비밀번호를 변경할 수 있다.
4. 계정이 비활성이면 포털 진입을 차단한다.

### 3.2 개별 계정 관리

1. 관리자 또는 교육담당자가 사용자 정보를 입력한다.
2. 시스템은 사번을 중복 확인하고 내부 인증용 이메일로 변환한다.
3. Auth 사용자와 프로필을 함께 생성한다.
4. 프로필 생성 실패 시 방금 생성한 Auth 사용자를 제거해 불완전 계정을 남기지 않는다.
5. 비활성화 시 프로필과 교육 이력은 보존한다.

### 3.3 Excel·CSV 일괄 등록

1. 담당자가 지정 헤더를 가진 `.xlsx` 또는 `.csv` 파일을 선택한다.
2. 시스템은 생성 전에 유효 행과 오류 행을 미리 보여준다.
3. 파일 내부 사번 중복, 필수값, 이메일 형식, 부서, 역할, 재직 상태를 검증한다.
4. 오류가 있으면 행 번호와 필드를 표시하고 확정 버튼을 비활성화한다.
5. 확정 시 같은 파일을 서버에서 다시 검증한 뒤 계정을 생성한다.

## 4. 사용자 데이터

- 사번
- 이름
- 부서
- 회사 이메일
- 재직 상태
- 직급
- 직책
- 휴대전화
- 입사일
- 역할
- 선호 언어

## 5. 화면 요구사항

- 로그인 화면
- 역할별 반응형 포털 셸
- 사용자 계정 목록, 검색, 역할·상태 필터
- 개별 사용자 등록·수정
- 계정 비활성화·재활성화
- Excel·CSV 업로드, 미리보기, 오류 다운로드
- 비밀번호 변경

모든 화면은 Arial을 사용하며, 기본 색상은 `#01916D`, `#34A78A`, `#67BDA7`, `#CCE9E2`, `#014937`이다. `#FB0020`은 오류·실패·긴급 상태에만 사용한다.

## 6. 데이터와 보안

- Supabase Auth와 PostgreSQL을 사용한다.
- 공개 스키마의 모든 테이블에 RLS를 적용한다.
- 익명 사용자는 프로필을 조회할 수 없다.
- 본인은 자신의 프로필과 언어 설정만 필요한 범위에서 접근한다.
- 관리자와 교육담당자는 업무에 필요한 사용자 정보를 조회한다.
- Supabase secret key는 서버 전용 모듈에서만 사용한다.
- 계정 로그인용 내부 이메일은 화면에 노출하지 않는다.

## 7. 인수 기준

- 사번과 최초 비밀번호로 로그인할 수 있다.
- 로그인한 사용자가 비밀번호를 변경할 수 있다.
- 비활성 계정은 포털에 진입할 수 없다.
- 역할별 메뉴와 서버 권한 검사가 일치한다.
- 관리자와 교육담당자가 개별 계정을 생성할 수 있다.
- Excel·CSV 파일을 미리 검증하고 유효한 계정을 일괄 생성할 수 있다.
- 익명 프로필 접근과 브라우저 비밀키 노출이 차단된다.
- 한국어·영어, Arial, 승인된 CI 색상이 데스크톱과 모바일에 적용된다.
- 린트, 타입 검사, 단위 테스트, 데이터베이스 테스트, 빌드, 핵심 E2E가 통과한다.
