# FBKR Learning Centre Portal 설계

작성일: 2026-09-17  
상태: 승인된 MVP 설계

## 1. 목적

FBKR Learning Centre Portal은 한국후지필름비즈니스이노베이션㈜의 반복적인 교육 운영을 자동화하는 반응형 웹 서비스다. 참가자는 PC와 모바일에서 교육 신청, 출석, 교육 이력 확인, 수료증 다운로드를 수행한다. 교육담당자는 전체 흐름을 다시 입력하는 대신 신청 승인과 예외 처리에 집중한다.

서비스의 모든 화면과 데이터 모델에서 교육 운영 단위는 `기수`가 아닌 `차수`로 표기한다.

## 2. MVP 범위

MVP에 포함한다.

- 시스템 관리자, 교육담당자, 참가자 계정과 역할별 접근 제어
- 과정과 단일 일정 차수 관리
- 참가자 직접 신청과 교육담당자 직접 배정
- 교육담당자 신청 승인, 정원 관리, 대기자 수동 확정
- 오프라인, 온라인, 혼합형 교육
- QR 또는 출석 코드와 담당자 수동 출석 처리
- 수료 자동 판정과 수료증 PDF 자동 발급
- 이메일과 사이트 내 알림
- 교육자료 파일과 외부 링크 제공
- 사용자와 과거 수료 결과의 Excel·CSV 업로드
- 참가자 명단, 출석부, 수료 결과의 Excel·CSV 내보내기
- 한국어·영어 UI와 OpenAI 기반 영문 콘텐츠 자동 생성
- PC와 모바일 반응형 화면

MVP에서 제외한다.

- 부서장·상급자 승인
- 강사 계정과 부서 교육담당자 역할
- 여러 차시로 구성된 차수
- 설문과 만족도 분석
- 과정별 자동화 규칙 편집 화면
- 문자와 카카오 알림톡
- Zoom·Teams 참석 기록 자동 연동
- 위치 기반 출석과 변경형 QR 코드
- 수료증 공개 진위 확인
- 과거 신청·취소·출석 상세 이력 이관
- 사용자 직접 회원가입
- 별도 모바일 앱
- 별도 백업 체계. MVP는 Supabase가 제공하는 기본 복구 기능만 사용하며 별도 백업은 운영 정책 확정 후 추가한다.

## 3. 사용자와 권한

### 3.1 시스템 관리자

- 모든 사용자, 과정, 차수, 신청, 출석, 수료 기록을 조회·수정한다.
- 사용자 계정을 생성·비활성화하고 역할을 지정한다.
- 교육담당자와 과정의 담당 관계를 관리한다.
- 카테고리와 시스템 설정을 관리한다.

### 3.2 교육담당자

- 자신이 담당하는 과정과 차수를 조회·수정한다.
- 담당 차수의 신청을 승인·반려하고 대기자를 확정한다.
- 담당 차수의 출석을 확인·수정하고 수료·발송 오류를 재처리한다.
- 사용자 계정을 개별 또는 파일로 등록할 수 있다.
- 과거 수료 결과를 파일로 가져올 수 있다.

### 3.3 참가자

- 공개된 모든 과정과 모집 중인 차수를 조회한다.
- 교육을 신청하고 취소 마감 전까지 직접 취소한다.
- 본인의 신청 상태, 출석, 수료 결과, 신규 수료증과 알림만 조회한다.
- 오프라인과 온라인 모두 PC 또는 모바일에서 QR·출석 코드를 사용할 수 있다.

Supabase RLS는 사용자 역할과 소유 관계를 모두 검사한다. 역할은 사용자가 수정할 수 없는 Auth `app_metadata`에 저장한다. 역할 변경 직후에는 해당 사용자의 세션을 갱신해 JWT의 오래된 역할 정보가 남지 않게 한다.

## 4. 인증과 사용자 관리

### 4.1 사번 로그인

- 화면의 로그인 ID는 개인 사번이다.
- 서버는 정규화한 사번을 내부 인증용 이메일 형식으로 변환해 Supabase 비밀번호 인증을 실행한다.
- 실제 회사 이메일은 프로필에 별도로 저장하고 업무 알림에 사용한다.
- 교육담당자 또는 시스템 관리자가 서버 전용 관리자 API로 계정을 만든다.
- 관리자 비밀키는 Vercel 서버 환경변수에만 저장한다.

최초 비밀번호는 사용자 요청에 따라 사번과 동일하게 설정한다. 최초 로그인 시 비밀번호 변경을 권고하지만 강제하지 않는다. 사용자는 로그인 후 비밀번호를 변경할 수 있다. 비밀번호를 잊은 경우 교육담당자 또는 시스템 관리자가 임시 비밀번호를 재설정한다.

### 4.2 사용자 데이터

프로필에는 다음 항목을 저장한다.

- 사번
- 이름
- 소속 부서
- 이메일
- 재직 상태
- 직급
- 직책
- 휴대전화
- 입사일
- 선호 언어

교육담당자는 표준 Excel·CSV 템플릿으로 사용자를 일괄 등록하거나 개별 등록한다. 사번 중복과 필수 항목 누락을 검사한다. 퇴직·사용 중지 사용자는 인증 접근만 비활성화하고 과거 교육 이력을 보존한다.

## 5. 교육 기준정보와 차수

### 5.1 과정

과정은 다음 정보를 가진다.

- 카테고리
- 국문·영문 과정명
- 국문·영문 설명
- 과정 활성 상태
- 반복 수강 허용 여부. MVP에서는 수료자의 재신청을 차단한다.
- 기본 수료 기준
- 담당 교육담당자

카테고리는 1단계 구조다. 시스템 관리자가 추가·수정·비활성화한다. 이미 사용한 카테고리는 삭제하지 않는다.

### 5.2 차수

한 차수는 하나의 시작·종료 일정을 가진다. 여러 날짜의 차시는 지원하지 않는다.

차수에는 다음 정보를 저장한다.

- 과정
- 모집 상태와 신청 기간
- 취소 마감 시각
- 시작·종료 시각과 Asia/Seoul 시간대
- 정원
- 운영 형태: 오프라인, 온라인, 혼합형
- 장소와 온라인 접속 링크
- 출석 허용 시작·종료 시각
- 지각 판정 기준 시각
- 사전 안내 발송 시점 목록
- 담당 교육담당자

모든 참가자에게 모집 중인 전체 과정과 차수를 공개한다.

## 6. 신청과 배정

### 6.1 참가자 신청

- 모든 직접 신청은 교육담당자의 승인을 거친다.
- 신청 전에 동일 차수 중복, 동일 과정 수료 이력, 확정 교육과의 일정 중복을 검사한다.
- 이미 해당 과정을 수료한 사용자는 다른 차수에도 신청할 수 없다.
- 미수료 또는 취소 이력만 있는 사용자는 다른 차수에 신청할 수 있다.
- 승인 시 정원이 남아 있으면 확정하고, 정원이 찼으면 대기 상태로 변경한다.

### 6.2 담당자 배정

- 교육담당자가 참가자를 개별 또는 일괄 배정할 수 있다.
- 배정은 별도 승인 없이 즉시 확정한다.
- 중복 수료와 일정 충돌 검사는 직접 신청과 동일하게 적용한다.

### 6.3 취소와 대기자

- 참가자는 차수의 취소 마감 전까지 직접 취소할 수 있다.
- 마감 후에는 교육담당자만 취소할 수 있다.
- 취소자가 생겨도 대기자를 자동 확정하지 않는다.
- 교육담당자가 대기자 중 한 명을 선택해 확정하며 시스템이 알림을 발송한다.

승인과 배정은 데이터베이스 트랜잭션에서 정원을 다시 검사해 동시 처리로 정원이 초과되지 않게 한다.

## 7. 출석과 수료

### 7.1 출석

- 참가자는 로그인한 상태에서 본인이 확정된 차수에만 출석할 수 있다.
- 차수에 설정된 출석 허용 시간에 QR을 스캔하거나 코드를 입력한다.
- 설정된 지각 기준 이전 체크인은 `출석`, 이후 체크인은 `지각`으로 기록한다.
- `조퇴`와 `결석`은 교육담당자가 수동 처리한다.
- 교육담당자는 모든 상태를 수정할 수 있으며 변경 전후 값, 수정자, 수정 시각을 기록한다.
- 동일 참가자의 중복 출석 시도는 한 건으로 처리하고 시도 이력을 남긴다.

### 7.2 수료

- `출석`과 `지각`은 수료다.
- `조퇴`와 `결석`은 미수료다.
- 교육 종료 후 자동화 작업이 수료 여부를 판정한다.
- 출석 상태가 변경되면 수료 결과를 다시 계산한다.
- 별도 예외 수료 승인 기능은 제공하지 않는다.

### 7.3 수료증

- 수료 대상자의 PDF를 자동 생성한다.
- 참가자 계정에 보관하고 회사 이메일로 발송한다.
- 발급·재발급 이력을 저장한다.
- 발급기관은 `한국후지필름비즈니스이노베이션㈜`로 표기한다.
- 대표이사명, 교육 책임자명, 서명, 직인을 표시하지 않는다.
- 시스템 발급 문구와 수료번호를 표시한다.
- 공개 검증 페이지와 검증번호는 제공하지 않는다.
- 과거 수료 결과를 가져올 때는 새 수료증을 생성하지 않는다.

수료증은 제공된 FUJIFILM PPT 템플릿의 시각 체계를 참고하되 전체 글꼴은 Arial을 사용한다.

## 8. 교육자료

- 한 차수에 여러 파일과 외부 링크를 등록할 수 있다.
- 파일은 Supabase Storage의 비공개 버킷에 저장한다.
- 확정 참가자와 담당 교육담당자만 접근한다.
- 허용 형식은 PDF, Word, Excel, PowerPoint, 이미지, ZIP이다.
- 파일당 최대 크기는 50MB다.
- 실행 파일과 스크립트 파일은 차단한다.
- 파일 업로드·삭제 이력을 남긴다.

## 9. 알림과 외부 서비스

### 9.1 알림 이벤트

다음 이벤트는 이메일과 사이트 내 알림을 생성한다.

- 신청 접수
- 신청 승인·반려
- 대기 등록과 대기자 확정
- 신청 취소
- 담당자 직접 배정
- 일정·장소·접속 링크 변경
- 차수별로 설정한 사전 안내
- 수료·미수료 결과
- 수료증 발급

일정·장소·링크가 바뀌면 확정 참가자에게 변경 전후 내용을 즉시 발송한다.

### 9.2 Microsoft 365

메일 전송 코드는 공급자 어댑터로 분리한다. 우선 구현은 Microsoft Graph를 기준으로 하며 사내 IT가 앱 등록을 허용하지 않으면 SMTP AUTH 어댑터로 교체한다. 자격 증명이 준비되기 전에는 개발용 기록 어댑터가 메일 본문과 수신자를 데이터베이스에 기록하며 외부 발송은 하지 않는다.

### 9.3 OpenAI 번역

- 담당자는 한국어 과정명, 설명, 안내 문구를 입력한다.
- 서버가 OpenAI API로 영어를 생성하고 즉시 공개한다.
- 번역 결과를 저장해 중복 호출을 피한다.
- 담당자는 영문을 직접 수정할 수 있다.
- 번역 실패 시 한국어 원문을 표시하고 실패 이력을 남긴다.
- OpenAI API 키는 Vercel 서버 환경변수에만 저장한다.

## 10. 과거 수료 결과 가져오기

표준 Excel·CSV 파일에서 다음 정보를 가져온다.

- 필수: 사번, 과정명, 교육일, 수료 여부
- 선택: 수료번호, 교육시간, 비고

업로드 순서는 파일 검사, 행별 검증, 미리보기, 사용자 확인, 최종 반영이다. 사번을 기존 사용자와 연결한다. 오류 행은 반영하지 않고 행 번호와 오류 사유를 결과 파일로 제공한다. 가져온 수료 결과는 재신청 차단 기준에 포함한다.

## 11. 화면 구조

### 11.1 교육담당자

- 홈 대시보드
- 과정 관리
- 차수 관리
- 신청 승인
- 참가자 관리
- 출석 관리
- 수료·수료증 관리
- 과거 수료 업로드
- 알림·메일 이력

홈 상단에는 오늘의 교육, 실시간 출석, 승인 대기, 발송 실패를 표시한다. 하단에는 모집 중인 차수, 신청자·확정자·대기자 수와 정원 충족률을 표시한다.

### 11.2 참가자

- 홈
- 교육 찾기
- 내 신청
- 출석
- 수료 이력
- 알림

홈 상단에는 예정 교육과 출석 동작을 표시한다. 그 아래에 신청 상태와 수료 이력·수료증을 표시한다.

### 11.3 디자인

- 서비스명: `FBKR Learning Centre Portal`
- 반응형 웹. 담당자는 PC 중심, 참가자는 PC와 모바일을 동등하게 지원한다.
- 한국어와 영어를 전환하고 사용자별 선택을 저장한다.
- 모든 글꼴은 Arial을 사용한다.
- 제공된 PPT의 흰색 배경, 넓은 여백, 얇은 검정 구분선과 정돈된 기업형 구성을 따른다.
- 기본 색은 Advanced Green 계열 `#01916D`, `#34A78A`, `#67BDA7`, `#CCE9E2`, `#014937`을 사용한다.
- 검정과 회색은 `#333333`, `#858585`, `#D6D6D6`을 사용한다.
- Communication Red `#FB0020`은 오류, 실패, 긴급 상태에만 제한적으로 사용한다.
- FUJIFILM 로고는 공식 원본 자산을 확보한 뒤 비율을 변경하지 않고 적용한다. 개발 중에는 텍스트 워드마크 자리표시자를 사용한다.

## 12. 기술 아키텍처

### 12.1 애플리케이션

- Next.js App Router와 TypeScript
- Vercel 배포와 Route Handlers
- 서버 컴포넌트 우선, 상호작용이 필요한 부분만 클라이언트 컴포넌트
- 국문·영문 메시지 사전과 사용자 언어 쿠키

### 12.2 Supabase

- PostgreSQL: 업무 데이터
- Auth: 사번 기반 비밀번호 로그인 매핑
- Storage: 비공개 교육자료와 수료증
- RLS: 역할, 담당 과정, 본인 데이터 접근 제어
- SQL migration: 모든 스키마 변경 이력 관리

새 테이블은 필요한 대상에만 Data API 접근 권한을 명시적으로 부여한다. 공개 스키마의 모든 테이블에 RLS를 활성화한다. 뷰는 `security_invoker`로 생성한다. 브라우저에는 publishable key만 제공하고 secret 또는 service role key를 제공하지 않는다.

### 12.3 GitHub와 Vercel

- 비공개 GitHub 저장소
- 기능 브랜치와 Pull Request
- `main` 병합 시 운영 자동 배포
- Pull Request별 Vercel Preview
- Preview는 Vercel 인증 사용자만 접근
- 사용자 선택에 따라 Preview와 운영이 같은 Supabase 프로젝트를 사용하고 실제 데이터를 수정할 수 있다.
- Preview 변경도 `audit_logs`에 배포 환경과 함께 기록한다.
- 자동 테스트는 운영 Supabase가 아닌 로컬 Supabase에서 실행한다.

### 12.4 환경변수

- Supabase URL과 publishable key
- Supabase secret 또는 service role key. 서버 전용
- OpenAI API key. 서버 전용
- Microsoft Graph 또는 SMTP 자격 증명. 서버 전용
- Cron secret. 서버 전용

`.env.example`에는 변수 이름만 기록하고 실제 값은 Git에 저장하지 않는다.

## 13. 자동화와 오류 처리

### 13.1 실행 방식

상태 변경 직후 실행한다.

- 신청·승인·대기·취소·배정 알림
- 일정 변경 알림
- OpenAI 번역
- 출석 반영

Vercel Cron이 하루 한 번 실행한다.

- 사전 안내 대상 조회와 발송
- 종료된 차수의 수료 판정
- 수료증 생성과 발송
- 1년이 지난 감사 로그 삭제

Cron은 UTC 기준으로 한국시간 오전 9시에 실행하며 `CRON_SECRET`으로 요청을 검증한다. Vercel Pro로 전환하면 같은 작업 처리기의 실행 주기만 단축할 수 있다.

### 13.2 중복과 재시도

- 자동 작업마다 업무 종류와 대상 ID로 중복 방지 키를 만든다.
- 같은 대상의 성공 작업은 다시 실행하지 않는다.
- 실패 사유, 시도 횟수, 마지막 시도 시각을 저장한다.
- 담당자는 실패 목록에서 수동 재실행할 수 있다.
- 수료 결과, 수료증, 발송 건에는 데이터베이스 고유 제약을 적용한다.

## 14. 데이터 내보내기와 감사

- 참가자 명단, 신청 상태, 출석부, 수료 결과를 Excel과 CSV로 내려받는다.
- 화면의 검색·필터 조건을 내보내기에 반영한다.
- 개인정보 파일 다운로드 사용자와 시각을 기록한다.
- 계정, 신청, 출석, 수료, 다운로드의 주요 변경을 감사 로그로 남긴다.
- 감사 로그는 1년간 보관하고 정기 삭제한다.
- 업무 원본 데이터는 비활성 계정 정책에 따라 계속 보존한다.

## 15. 핵심 데이터 모델

- `profiles`: 사용자 업무 프로필
- `departments`: 부서
- `categories`: 과정 카테고리
- `courses`: 과정 마스터와 국문·영문 콘텐츠
- `course_sessions`: 차수와 단일 일정
- `session_reminders`: 차수별 사전 안내 시점
- `enrollments`: 신청, 배정, 승인, 대기, 취소 상태
- `attendance_records`: 출석 상태와 변경 이력 연결
- `completions`: 수료 판정과 과거 수료 결과
- `certificates`: 신규 수료증 발급·재발급
- `course_materials`: 비공개 파일과 외부 링크
- `notifications`: 사이트 내 알림
- `email_deliveries`: 이메일 전송과 재시도
- `automation_jobs`: 예약·실패·중복 방지 상태
- `completion_import_batches`: 과거 이력 업로드 작업
- `completion_import_rows`: 행별 검증과 반영 결과
- `audit_logs`: 주요 변경과 다운로드 기록

각 업무 테이블에는 UUID 기본키, 생성·수정 시각을 둔다. 상태는 제한된 enum 또는 check constraint로 검증한다. 삭제보다 비활성화와 상태 전환을 우선한다.

## 16. 테스트와 완료 기준

### 16.1 자동 테스트

- 수료 판정, 일정 중복, 수료자 재신청 차단, 취소 마감 단위 테스트
- 시스템 관리자, 교육담당자, 참가자 RLS 테스트
- 정원 동시 승인과 중복 작업 통합 테스트
- 사용자·과거 수료 파일 업로드 검증 테스트
- 한국어·영어 전환과 번역 실패 테스트
- 이메일·수료증 중복 방지와 재실행 테스트
- Playwright 기반 핵심 브라우저 흐름 테스트

### 16.2 사용자 흐름 완료 기준

다음 흐름이 PC와 모바일에서 완료되어야 한다.

1. 교육담당자가 계정과 과정을 등록한다.
2. 차수를 개설하고 자료와 안내 시점을 설정한다.
3. 참가자가 신청하고 교육담당자가 승인한다.
4. 참가자가 QR·코드로 출석한다.
5. 종료 후 시스템이 수료를 판정한다.
6. 시스템이 수료증을 만들고 참가자에게 제공한다.
7. 교육담당자가 오류와 발송 이력을 확인한다.

## 17. 개발 단위

구현은 다음 독립 단위로 나눈다.

1. 프로젝트 기반과 디자인 시스템
2. Supabase 스키마, RLS, 인증
3. 사용자 등록과 역할 관리
4. 과정·카테고리·차수
5. 신청·승인·배정·대기·취소
6. 참가자 홈과 교육 찾기
7. QR·코드 출석과 담당자 출석 관리
8. 수료 판정과 수료증
9. 알림, Microsoft 365 어댑터, OpenAI 번역
10. 교육자료와 파일 권한
11. 과거 수료 가져오기와 데이터 내보내기
12. 자동화, 감사 로그, 통합 검증

각 단위는 데이터베이스 정책, 서버 로직, 화면, 자동 테스트를 함께 완료한다.
